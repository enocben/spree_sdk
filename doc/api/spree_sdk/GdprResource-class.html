GdprResource

GdprResource class

GDPR data-request operations: the authenticated /customers/me collection plus the token-based (credential-less) endpoints.

final gdpr = GdprResource(client);
final DataRequest req = await gdpr.create(
  params: CreateDataRequestParams(type: 'export'),
  options: RequestOptions(token: jwt),
);
// ... user clicks the email link (user gesture only) ...
await gdpr.confirm(tokenFromLink);

Methods

confirm(String token, {RequestOptions? options}) → Future<DataRequest>
POST /data_requests/{token}/confirmation → DataRequest, starts processing. No credential (see getByToken). Call only on explicit user gesture — mail scanners prefetch email links (flows §I).
create({required CreateDataRequestParams params, RequestOptions? options}) → Future<DataRequest>
POST /customers/me/data_requests → created DataRequest in awaiting_confirmation status. Auth: KEY+JWT.
get(String id, {RequestOptions? options}) → Future<DataRequest>
GET /customers/me/data_requests/{id} → single DataRequest.
getByToken(String token, {RequestOptions? options}) → Future<DataRequest>
GET /data_requests/{token} → DataRequest, carrying the download link when ready. No credential: the email-link token (path segment, percent-encoded by the transport) is the credential — any configured JWT is deliberately not sent. options carries only non-credential context (locale, timeout, …).
list({ListQuery? list, Map<String, String>? query, RequestOptions? options}) → Future<PaginatedResponse<DataRequest>>
GET /customers/me/data_requests → paged DataRequest entries (most recent first). Auth: KEY+JWT.
